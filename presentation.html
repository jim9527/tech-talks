Pain of Traditional E2E

✗ Slow to write — massive boilerplate

✗ Fragile selectors — UI change = all fail

✗ Flaky timing — async race conditions

✗ High maintenance cost

✗ Hard to debug failures in CI

Real cost

A team of 5 engineers spending 20% of sprint time on flaky tests = 1 full engineer lost


"Writing tests is more painful than writing features"

Skill Files: Teaching AI Your Conventions

What is a skill file?

A markdown file at .claude/skills/playwright.md that tells the AI agent:

  • Which selectors to use
  • How auth works in this project
  • When to mock vs use real backend
  • Anti-patterns to avoid

Why not just prompt?

  • Persists across sessions
  • Shared with the whole team
  • Version-controlled in git
  • Loaded automatically by the agent

One skill file = consistent tests from every engineer

  .claude/
  └── skills/
      └── playwright.md   ← manually copied, team-owned convention guide

Prompt is the New Test Case

Structured prompt template

Feature: Inventory page
Test goal: User can add item to cart
Base URL: https://www.saucedemo.com
Steps:
  1. Navigate to /inventory.html
  2. Click "Add to cart" on Backpack
  3. Check cart badge shows "1"
Assertions:
  - Cart badge text equals "1"
Edge cases:
  - Adding same item twice

AI generates

test('add item to cart', async ({ page }) => {
  await page.goto('/inventory.html');
  await page.locator(
    '[data-test="add-to-cart-sauce-labs-backpack"]'
  ).click();

  await expect(
    page.locator('.shopping_cart_badge')
  ).toHaveText('1');
});

High-quality prompt = high-quality test. Garbage in, garbage out.

Selector Strategy Hierarchy

  Priority 1 (BEST)   getByTestId('login-button')
                           │  stable, decoupled from UI
                           │
  Priority 2          getByRole('button', { name: 'Login' })
                           │  semantic, accessible
                           │
  Priority 3          getByLabel('Email address')
                           │  for form fields
                           │
  Priority 4 (LAST)   locator('.btn-primary')
                           │  brittle — breaks on CSS refactor
                           │
  NEVER               locator('//div/button[1]')
                           XPath — unmaintainable

Add data-testid attributes to your components. This is a frontend contract with your tests.

Auth at Scale: storageState Pattern

  WITHOUT storageState (naive)          WITH storageState (correct)

  test 1: login → do thing              globalSetup runs ONCE:
  test 2: login → do thing                login → save auth/user.json
  test 3: login → do thing                        │
  test 4: login → do thing              ┌─────────┴──────────┐
  test 5: login → do thing              │  playwright.config  │
                                        │  storageState:      │
  5 logins × N tests = slow,            │  'auth/user.json'   │
  flaky, brittle                        └─────────┬──────────┘
                                                  │ inherited by ALL tests
                                        test 1: already logged in ✓
                                        test 2: already logged in ✓
                                        test 3: already logged in ✓

Exception: login.spec.ts opts out with test.use({ storageState: { cookies: [], origins: [] } })

Code: storageState in Practice

auth/setup.ts

import { chromium } from '@playwright/test';

async function globalSetup() {
  const browser = await chromium.launch();
  const page = await browser.newPage();

  await page.goto('https://www.saucedemo.com/');
  await page.getByTestId('username')
    .fill('standard_user');
  await page.getByTestId('password')
    .fill('secret_sauce');
  await page.getByTestId('login-button').click();

  await page.waitForURL(/inventory/);
  await page.context().storageState({
    path: 'auth/user.json'  // gitignored
  });
  await browser.close();
}
export default globalSetup;

playwright.config.ts

export default defineConfig({
  globalSetup: './auth/setup.ts',
  use: {
    baseURL: 'https://www.saucedemo.com',
    storageState: 'auth/user.json',
  },
  projects: [
    {
      name: 'setup',
      testMatch: /auth\/setup\.ts/,
    },
    {
      name: 'chromium',
      use: { ...devices['Desktop Chrome'] },
      dependencies: ['setup'],
    },
  ],
});

Engineered Test Structure

import { test, expect } from '@playwright/test';

// login.spec.ts — opts out of global storageState
test.use({ storageState: { cookies: [], origins: [] } });

test.describe('Login Flow', () => {
  test('user can login and see inventory', async ({ page }) => {
    await page.goto('https://www.saucedemo.com/');

    await page.getByTestId('username').fill('standard_user');
    await page.getByTestId('password').fill('secret_sauce');
    await page.getByTestId('login-button').click();

    await expect(page).toHaveURL(/inventory/);
    await expect(page.locator('.inventory_item')).toBeVisible();
  });

  test('locked_out_user sees error', async ({ page }) => {
    await page.goto('/');
    await page.getByTestId('username').fill('locked_out_user');
    await page.getByTestId('password').fill('secret_sauce');
    await page.getByTestId('login-button').click();

    await expect(page.getByTestId('error-button')).toBeVisible();
  });
});

Anti-Patterns That Kill Test Suites

Never do this

// FLAKY — arbitrary wait
await page.waitForTimeout(2000);

// BRITTLE — breaks on CSS refactor
await page.$('.btn-primary');

// BLOCKS CI — never commit
test.only('my test', ...);

// SHARED STATE — tests interfere
let cart = [];
test('adds item', () => cart.push(1));
test('checks cart', () => expect(cart));

Do this instead

// Auto-wait on element
await expect(locator).toBeVisible();

// Stable test-id selector
await page.getByTestId('submit-btn');

// Tag for selective runs
test('my test', { tag: '@smoke' }, ...);

// Independent state per test
test.beforeEach(async ({ page }) => {
  await page.goto('/cart');
  // fresh state every time
});
If you can't read your test, you don't own your test

Scaling Patterns (Staff Level)

1. Page Object Model

class LoginPage {
  constructor(private page: Page) {}

  async login(user: string, pass: string) {
    await this.page.getByTestId('username')
      .fill(user);
    await this.page.getByTestId('password')
      .fill(pass);
    await this.page.getByTestId('login-button')
      .click();
  }
}

2. Test Layering

Smoke (5 tests, 2 min) → Regression (50 tests, 15 min) → Full (200 tests, 1 hr)

AI Limitations You Must Know

⚠ Hallucinated selectors
AI invents data-testid values that don't exist. Always verify against the DOM.


⚠ Happy path bias
AI writes the success case. You must prompt explicitly for error states, edge cases, and race conditions.

⚠ Stale context
AI doesn't know your app changed. Skill files help, but human review is non-negotiable.


⚠ No visual reasoning
AI can't see the page. It can't detect layout regressions, z-index issues, or overlapping elements.


AI owns the "how". You own the "what" and the "whether it's correct".

Key Takeaways

1. Write a skill file — teach AI your project's conventions once

2. Add data-testid to your components — it's a contract with your tests

3. Adopt storageState — login once, run fast

4. Define your mock policy — document when to mock in every page.route()

5. Human review is non-negotiable — AI accelerates, humans own quality

  Prompt = new abstraction layer
